Two spreadsheets, one sheet

The same grid, the same formula language, the same instrumentation. What differs is who keeps the values and who decides what has to be redrawn.

  • Classic — state by hand: a dependency graph, a topological order, invalidation.
  • On weft — a cell is an input, a value is a formula; dependencies come from reading.

Open them in two tabs and edit A1 in both.

One sheet, many windows

The same sheet, living outside any window. Whichever window holds the lock computes it; every window watches it over the tab bus — the leading one included. Edit in either window and both follow. Close the leading window: the other takes the sheet over by the freed lock, and every mirror re-asks on its own. This is the page that is not a wrapper over React — React only draws it.

Kanban, twice

The classic side — redux + redux-observable, written the usual honest way: normalized state, optimistic moves with rollback bookkeeping, polling with a hand guard. Drag cards; some writes get refused on purpose and roll back before your eyes. The weft side comes after this one stands trial.

A rail that feeds itself

Pages from a server, a live feed on top. The state module declares what things are — a table with a precedence rule, shelves, counters — and holds not a single reducer. The feed starts with the first look and rests when nobody watches; a page that travelled slowly loses to the event that overtook it. Watch the render counter while scores tick.
