Two spreadsheets, one sheet

The same grid, the same formula language, the same instrumentation. What differs is who keeps the values and who decides what has to be redrawn.

  • Classic — state by hand: a dependency graph, a topological order, invalidation.
  • On weft — a cell is an input, a value is a formula; dependencies come from reading.

Open them in two tabs and edit A1 in both.

Kanban, twice

The same board, the same grumpy server, the same shadcn screen. What differs is the state layer. Drag cards; every eighth write is refused on purpose and rolls back before your eyes; a bot keeps editing the board so it goes stale on its own.

  • Classic — redux + redux-observable: actions, a reducer with rollback bookkeeping, epics, selectors.
  • On weft — one state file: each action is one function holding its hope, its ask and its retreat.
  • Carried — the same board in every tab: one leads and serves, the rest mirror. Close the leader and the lock hands the station over; the book survives the succession.

A rail that feeds itself

Pages from a server, a live feed on top. The state module declares what things are — a table with a precedence rule, shelves, counters — and holds not a single reducer. The feed starts with the first look and rests when nobody watches; a page that travelled slowly loses to the event that overtook it. Watch the render counter while scores tick.

An engine behind a wire

A state module in a worker, panels holding mirrors. The engine works while a panel watches it and stops when the panel closes — the tick counter says so. Kill the worker with the button: the mirrors ask again by themselves, and nothing in the panel code knows it happened.

A table that lives in another thread

A hundred thousand rows held by a worker, twenty of them on screen. Scrolling writes where the window starts and reads back exactly the rows that fit — the counter says how few crossed. An edit half-typed survives its row scrolling out of sight, because the draft is a cell of its own rather than a field of the row.

A whole table, followed over a wire

The protocol underneath: a snapshot, then batches of what changed. A worker keeps pouring rows in and editing them; a switch on the page makes the wire drop batches, and the follower notices instead of quietly showing the wrong thing — the last good rows stay up, labelled, until the catch-up lands.
